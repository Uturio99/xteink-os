# XTEInk X4 Pro — product contract and execution plan

**For PO acceptance · 2026-11-05. Next gate: WP2.4, FR-01 Home milestone.** This is the execution plan for the downstream firmware. Accepting the document does not accept a firmware checkpoint, authorize a flash or start a later package.

## Product and authority

A reader should be able to resume a Vietnamese book, find or import another, adjust reading controls and return to the same passage. The redesign changes how existing CrossPoint features appear and how the reader reaches them. Success means all five [M1 journeys](design/specs/UNIFIED_UI_COLLECTION.md) work on X4 Pro with legible diacritics, reliable touch and mapped buttons, one clear primary action, no lost reading state, and measured panel response. The four **visible deliveries** below group existing WPs; M0–M7 in [project status](PROJECT_STATUS.md) remain program and engineering checkpoints, not seven new products.

**Hardware contract.** [Board profile](../platformio.ini) lines 392–412 and [pinned SDK board notes](../freeink-sdk/docs/xteink-x4pro-support.md): X4 Pro is ESP32-S3, 16 MB flash, 8 MB PSRAM, 800×480 E-Ink panel, 480×800 logical portrait, GT911 touch and physical controls. Controller varies (SSD1677/UC8179/UC8279); identify the tested unit. Use existing orientation and refresh policy. M1 requires readable 1-bit output, NFC UI copy, ≥48×48 hit areas and ≥56 px primary/repeated actions; grayscale is never the only cue. Shared paths must also fit the single-buffer, no-PSRAM X3/X4 ESP32-C3. Measure internal and external heap separately, including largest free block; PSRAM is not a cure for internal fragmentation.

**Scope.** Home, local Library and import, presentation of Reader and Settings, Vietnamese type and accessible E-Ink interactions are in scope. Keep working formats (including existing MD/XTCH handling), progress/resume, TOC, buttons, protected-content handling, current transfer/OPDS/plugin access, settings and recovery. No new format promise beyond PD-1; no PDF/FB2 engine, connector, built-in theme framework, new reader, always-on Wi-Fi, cloud curation or database. Preserve existing functionality and other boards' layout/input by default.

| XTEInk UI/UX | [CoverGridHomeUi](../src/components/CoverGridHomeUi.cpp), [X4ProHomeLayout](../src/components/X4ProHomeLayout.h), [UITheme](../src/components/UITheme.cpp), existing activity/FreeInkUI controls and [i18n](../lib/I18n/translations/) | Customize X4 Pro presentation and selection in place. Preserve mapped-input ownership, other-board paths, rotation and exits. Use existing font slots and HAL rendering. No framework, global theme rewrite or speculative driver tuning. |

For each change: eliminate unnecessary output → reuse the owner above → use a native capability → use an installed dependency → make the smallest local change. No automatic sync, rebase, merge, revert or dependency update. A future sync needs a named upstream target, a reason, affected paths, candidate/regression evidence and separate PO direction.
