## Route ownership and blockers for STEP 05

- **NAV-001 implementation contract:** the existing activity stack is the smallest mechanism. Library launches Reader as a child with a return callback. Library retains its own tab/list/query/selection/viewport fields. Its index is closed before Reader and must be reopened/reconciled on return. Reader alone writes reading progress. No global or persistent duplicate Library state.
- **Route missing in baseline:** Library→Files direct transition is not evidenced by inspected Library controls. Decide whether XTEInk needs this direct shortcut; otherwise Files remains reachable from Home.
- **Unsafe assumptions to reject:** treat USB MSC as an activity that can simply pop back; allow filesystem access while host owns SD; conflate Wi-Fi credentials with transfer service; use Home’s progress preview as progress writer; assume Reader Back currently restores Library; assume gesture/eject behavior from source.
- **Verification required later:** Library stack retention and index reopen under SD handle limits; removed/reordered book fallback; touch-only contextual Back and independent Home; each mapped button and swipe; Wi-Fi failure return; USB host eject/unplug/restart/remount; progress reopen for EPUB/XTC and interrupted-write boundary. Source inspection alone does not close these runtime/device checks.
- **STEP 05 blockers:** resolve the Library→Files product route only if required; carry NAV-001 stack/return contract into visual flow; preserve explicit Home, touch Back reachability and Files shortcut. No additional architecture or UI design is authorized by this trace.
