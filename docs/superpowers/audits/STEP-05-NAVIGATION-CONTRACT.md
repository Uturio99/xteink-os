**Reachability decisions for design.** Keep Files and Transfer reachable via Home from Library. The explicit Home action offers a one-action exit even when Library Back must first clear a query or move focus. Neither a direct Library → Files button nor a direct Library → Transfer button is required for parity. Keep Import visible on empty Home and under Files/System as specified in the product contract. Those placements route to the *same* transfer owner. Library Discover is an entry to OPDS, while editing servers stays under Network. At zero servers, point to the existing add-server path. A Settings → Extensions catalog entry, must push the existing non-root catalog and respect the enable gate. Calling `goToPlugins` there would clear Settings. These are presentation bindings, not baseline caller claims.

## NAV-001 · One Library visit owns its Reader return

**Approved outcome.** For a book opened from Library, contextual Back returns to its originating Library, preserving viewport and focused book. Explicit Home ends the visit. Page progress uses the existing format-specific writers, including the sync path that applies remote EPUB progress. The following lifecycle is an implementation requirement for a later package.

1. **Open.** Both row activation and Recent → Open resolve the book path through `LibraryListActivity::openBookByPath`. Keep the existing Library instance, `tabNavs`, sort direction, search and group state. Use the launched path as the visit's identity for the return callback. Close the index and clear stale touch routing before Reader uses storage. Create the normal format reader and push it with `Activity::startActivityForResult`. The global `goToReader` replaces the whole stack and stays appropriate for root launches. Failure to allocate/start the child must leave Library usable and its index reconciled.
2. **Exit.** The contextual command finishes the active Reader through the manager. Pop calls Reader exit/destruction under the render lock, restores the parent, then invokes its one-shot result callback outside that lock. Pop skips Library `onEnter`. The callback must prepare the data before the next paint and use normal locking around index/list mutations. Home calls `goHome` and Files uses `goToFileBrowser(bookPath)`; either replacement releases the stacked Library via `onExit`. Neither destination may briefly open Library or replay its callback.
3. **Reconcile.** Reopen the index under the existing SD ownership rules. Check dirty/invalid/metadata mismatch just as Library does on entry. Refresh filtered/grouped rows and pinned Recent identities from live sources before trusting any ordinal. Restore the matching path, tab, sort, query, group state, strip/row focus and top row. If ordering is unchanged, restore the exact viewport. If reordered, preserve the old top where valid and move it only as much as needed to keep the same book visible. Clamp against the new count. Do not rerun tab selection that resets the top to zero.
4. **Invalid state.** If the book was removed or moved and the unfiltered list survives, focus the nearest valid row, without opening it. If the query no longer includes the book, keep the query and focus its tab strip. For an empty list, use strip focus and a valid empty viewport. If index reopen/rebuild or filter allocation fails, invalidate stale ordinals and show only safely available rows or the existing degraded/empty state; Back/Home must still work. Reader load failure that finishes a pushed child returns through the same reconciliation. Cold boot, sleep replacement and explicit root navigation do not restore a stale in-memory visit.
5. **Same-book detours.** A simple push at Library entry alone fails after KOReader sync or protected-loan time-sync relaunch. Baseline sync replaces Reader with Sync and then reopens the same path by replacement. On X4 Pro, successful loan time sync can also relaunch in place by replacement. Both would erase the Library parent. The later integration must preserve the existing parent for those in-session same-book transitions while freeing Reader resources as the current code requires. Use the existing manager's ownership of the stack; do not retain a second Reader, make a global origin registry or persist a Library snapshot. Verify sync success, cancel/failure, loan retry/cancel and true reboot separately. An explicit end-of-book suggestion opens a *different* book and keeps its replacement semantics.
