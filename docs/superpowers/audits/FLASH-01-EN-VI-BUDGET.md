# FLASH-01 — Flash budget breakdown for an English + Vietnamese-only firmware (x4pro)

**Status:** MEASURED (linker-level, `nm --print-size` on `firmware.elf`).
**Base:** `~/noveos-rec02b` @ d30e6a12, `.pio/build/x4pro/firmware.elf` (Flash 5,937,274 / 6,553,600).
**Scope:** measurement only. PO decision 2026-11-22: UI languages and built-in content support = English + Vietnamese only. FIX-01b cancelled.

All sizes are bytes as linked (`.rodata`/`.text` + static data). Category totals verified against the ELF symbol table.

## 1. I18n strings — ~402 KB total, ~376 KB removable

`lib/I18n/I18nStrings.cpp` (generated by `scripts/gen_i18n.py` from `lib/I18n/translations/*.yaml`):

- 35 language string blobs (`STRINGS_<cc>_DATA`): **355,659 B** total; EN 11,221; VI 12,115; non-EN/VI **332,323 B**.
- 35 offset tables (`OFFSETS_<cc>`, 0x52e = 1,326 B each) + language-name/character tables: **46,830 B** total; non-EN/VI ≈ **43,758 B**.
- **Total removable ≈ 376,081 B** (33 languages).

Language references: `Language` enum in `lib/I18n/I18nKeys.h` (~line 82, one enum + `languageName`/`languageBcp47` switch); picker in `LanguageSelectActivity`. Keyboard-layout and hyphenation references go through the enum, not the string tables.

**Allowlist already exists:** `gen_i18n.py` supports `builtin_langs` (comma-separated list, e.g. `"EN,VI"`); `parse_builtin_langs()` (gen_i18n.py:848) forces EN in and errors on unknown codes. Non-builtin languages keep their enum/code/name so dependent code still compiles; they just lose string tables and picker entries. A build-time allowlist needs **only a generator invocation change** — verify how `builtin_langs` is wired into the build (it is a `main()` param; check whether SCons/platformio passes it or whether it needs a build flag).

## 2. Built-in fonts — ~1.24 MB total; ~250–300 KB removable (estimate)

Linked as: 16 notosans faces (4 sizes × regular/bold/italic/bolditalic, compressed 2-bit, `--compress --zopfli`) + 5 ubuntu faces (8/10/12 regular, 10/12 bold, uncompressed 2-bit).

| Family | Linked bytes | Glyphs/face | Intervals/face | Non-Latin/VI cps |
|---|---|---|---|---|
| notosans_12..18 ×4 styles | **916,961** | ~1,072 | 20 | ~263 (256 Cyrillic 0x400–0x4FF + ~7 strays) |
| ubuntu_8/10/12 ×5 faces | **319,305** | 1,313 | 51 | ~802 (Cyrillic, Hebrew 0x5D0–0x5EA, Arabic 0x60C–0x6F9, Arabic presentation forms FB56–FEFC, math/strays) |
| other font infra | ~8,500 | — | — | — |

Per-face array sizes: notosans bitmaps (compressed) 23,118–50,065 B, glyph records 17,152 B; ubuntu bitmaps (raw) 18,320–42,356 B, glyph records 21,008 B. Plus per-face kern/ligature/group/interval tables (FONT_meta category total **137,033 B** across all 21 faces).

Interval coverage (parsed from headers): notosans keeps Latin, combining marks 0x300–0x36F, Vietnamese 0x1EA0–0x1EF9, punctuation/currency/superscripts, math 0x2200–0x22FF, arrows 0x2190–0x21FF — and **Cyrillic 0x400–0x4FF**. Ubuntu additionally carries Hebrew, Arabic blocks and Arabic presentation forms (why Arabic UI text renders today).

**Removal estimate** (not measured exactly — compressed groups mix glyphs):
- Glyph records: notosans ~263 cps × 16 B × 16 faces ≈ 67 KB; ubuntu ~802 × 16 B × 5 ≈ 64 KB → ~131 KB.
- Bitmaps: notosans compressed — Cyrillic glyphs are ~24% of the glyph count; proportional share ≈ 200–230 KB (upper bound; compression regroups change this). Ubuntu uncompressed — per-glyph `dataLength` sums give an exact number cheaply if wanted.
- **Realistic total ≈ 300–350 KB** across both families if Cyrillic/Hebrew/Arabic/math/arrows are dropped; less if math/symbols are kept.
- **Risk:** removing Cyrillic breaks the FIX-01 fallback that currently renders Russian/Cyrillic book metadata; Hebrew UI strings exist (HE language). EN+VI-only books still need Latin-Ext + combining marks + VI 0x1EA0–0x1EF9.

**Regeneration:** headers are generated by `lib/EpdFont/scripts/fontconvert.py` (command in each header comment: `fontconvert.py <name> <size> <ttf> --2bit --compress --pnum --zopfli`). The codepoint list is a hardcoded `intervals` table in fontconvert.py:44–112 with `--additional-intervals` for extras. A Latin+VI-only build = edit the interval list (or add a flag) and re-run for all 21 fonts — fully reproducible, sources in `lib/EpdFont/builtinFonts/source/`.

**No Vietnamese hyphenator exists** — keeping EN+VI means keeping only `en` (26,943 B): removable **324,515 B** by dropping 10 `kEntries` rows + their includes. ## 4. Keyboard layouts — small (~few KB), app-controlled

`fui::keyboard` layout tables live in the pinned SDK (`builtinKeyboardLayout(...)`); linked cost is small (a few KB of row descriptors — nothing ≥4 KB appears in the symbol table). The app-level selectable list is `src/activities/util/KeyboardLayoutSet.h` `ALL[]` — **10 layouts**: QwertyEn, AzertyFr, QwertzDe, SpanishEs, CyrillicRu/Uk/Be/Kk, HebrewIl, ArabicAr. EN+VI-only could reduce `ALL[]` to `{QwertyEn}` — but `LATIN_BITS` logic and the persisted bitmask (`static_assert COUNT<=16`) mean the savings are tiny (~1–2 KB + a settings screen simplification). **No dedicated Vietnamese input method exists** — VI is typed via the Latin layouts (precomposed Unicode).

## 5. Bidi / Arabic shaping / combining marks — small

- `arab_shaping.h` (SDK FreeInkBook): ~6 KB static table (header source); linked cost a few KB.
- Bidi workspace + arabic presentation-form detection: tens of bytes of tables + ~1–2 KB code (`MiniBidi`, `appendShapedRtlTokens`).
- `utf8IsCombiningMark`, `combiningMark::anchorFor`: tiny; **required for Vietnamese** (stacked diacritics) — keep.
- Not worth removing: ~10 KB max, and RTL still needed if Arabic/Hebrew book content is readable via SD fonts.
